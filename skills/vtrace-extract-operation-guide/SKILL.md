# VTrace 操作指南

将视频中确有依据的操作整理成可执行、可回看的指南。生成指南不代表执行指南中的命令、修改配置或操作外部服务。

## 连接与视频选择

- 使用已配置的 VTrace MCP。`seeit-ai` 连接标识、`seeit://` 资源 URI、`SEEIT_*` 环境变量是兼容名称，不因项目更名自行替换；MCP 仍调用 Python API。
- 从用户给定的 `media_id` 开始；缺失时调用 `list_media` 定位，结合用户上下文能确定时直接使用，否则询问。调用 `get_video_metadata` 核对来源和证据数量。
- 对尚未入库的 BV 视频，预览后导入并通过 `get_bilibili_import_status` 等待 `mediaId`；不要把导入任务 ID 当视频 ID。本地文件由网站上传，MCP 当前不提供文件上传工具。
- 保持现有用户鉴权；连接或权限失败应说明实际错误，不能读取其他用户资源或暴露 Token。

## 证据工作流

1. 使用 `get_video_timeline` 按时间范围浏览操作顺序，再使用 `search_video_evidence` 检索前提、动作、参数、验证与失败排查。单次时间轴最多 200 条，达到上限时拆小时间范围并去重，不把首批结果当作全部步骤。
2. 搜索可围绕“安装、配置、登录、首先、选择、输入、运行、检查、失败”等动作与对象展开，优先 `sources=["ASR", "OCR"]`。检查覆盖与证据充分性信息（若有），`SYSTEM` 占位内容不能生成操作步骤。
3. 对候选步骤调用 `get_evidence_window`，补足操作对象、参数、前后依赖和结果。OCR 中出现按钮或命令文字，不代表视频实际点击或执行了它；没有视觉语义工具时不能编造鼠标操作。
4. 按原始 `startMs` 整理流程，合并同一步骤的 ASR/OCR。区分初次失败尝试、纠正步骤、替代方案和最终成功路径，不能把互斥方案串成必须依次执行的流程。
5. 用 `verify_video_citations(media_id, citations)` 校验最终引用，保留原始毫秒时间戳、来源和文本。除工具结果外，核对语义、否定条件及参数单位；校验失败时回到证据修订。

## 输出

优先遵守用户格式；默认提供适用场景、前置条件、编号步骤、验证方法及有证据的注意事项和失败排查。

- 步骤包含动作、对象、视频明确给出的参数和预期结果，附 `[MM:SS]` 与 ASR/OCR 来源。
- 不补造安装命令、文件路径、口令、版本号或缺失的中间步骤；写明“视频未展示”或“参数未明确”。用户另外要求的通用建议应单列为补充。
- OCR 可能漏掉短暂画面，采样时间不是每个操作的精确发生时间；读不清的文字、时序冲突和证据缺口应提示复核。
- 若有依据推断步骤关系，明确标注推断；不能把推断当作视频演示过的事实。

## 平台报告与追问

证据需要异步准备或用户要求保存指南时，调用 `start_video_analysis(media_id, goal)`，目标示例：“提取视频中的前置条件、按序操作、明确参数、验证结果和失败排查，区分失败尝试与成功路径，并引用时间戳”。

用 `get_analysis_status(task_id)` 轮询，间隔不少于 3 秒；复用重复任务响应中的 ID，没有 ID 时用同目标 `get_analysis_report` 查找，不连续创建相同任务。`FAILED` 要说明错误；`COMPLETED` 后读取报告并检查 `answerable`，拒答结果不能包装成完整 SOP。尚未完成而需要交还控制权时，返回任务 ID、当前状态及未完成事项。

针对已生成指南的后续问题可用 `ask_video`，需要历史时用 `get_agent_memory`；补充步骤仍应回到原始证据。
