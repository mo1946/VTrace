# VTrace 证据审计

逐条检查视频结论是否受到原始证据支持。报告、模型回答和会话历史都是待核验材料，不能作为证明自身正确的依据。

## 连接与审计对象

- 使用 VTrace MCP；当前兼容连接标识仍为 `seeit-ai`，资源仍使用 `seeit://`，鉴权与环境配置仍为 `SEEIT_*`。工具转发 Python API，不直接访问共享数据库或绕过用户权限。
- 确定视频 `media_id` 和待审计文本。未给视频时用 `list_media` 定位，歧义无法消除时询问；未给报告时用 `get_analysis_report(media_id, goal)` 读取对应目标的报告。
- 报告不存在或任务未完成时说明实际状态，不把空响应当作审计通过，也不自动创建新分析覆盖审计对象。若用户另行要求生成报告，再按该授权启动分析。
- 调用 `get_video_metadata` 检查证据情况。鉴权、服务异常、未提取证据和已检索但未命中应分别说明；`SYSTEM` 占位文本不算视频事实证据。

## 核验流程

1. 把待审计文本拆成可独立验证的事实项，记录比较对象、数值、限定条件、负责人、时间范围及原引用。需要多条证据的结论不能因其中一项命中就整体通过。
2. 对已有引用调用 `verify_video_citations(media_id, citations)`，每条引用使用 `timestampMs`、`source`、`content`；时间参数为毫秒，展示文本再转换为 `[MM:SS]`。检查引用确实来自当前视频。
3. 无引用或校验失败时，用 `search_video_evidence` 搜索实体、动作及对立表述，优先 ASR/OCR。检查返回的 `coveragePlan`、`evidenceSufficiency`（若有），不以高相似度或关键词重合直接判定支持。
4. 用 `get_evidence_window` 展开前后文，检查否定、条件、修订、引用他人观点及后续反驳。需要核查某个时间范围时使用 `get_video_timeline`；单次最多 200 条，达到上限时缩小窗口并去重，记录未覆盖范围。
5. 区分引用有效性与结论支持度。程序校验通过仅表示达到其匹配规则，仍需语义判断；引用错误也不自动证明结论为假，应继续寻找原始依据。
6. ASR/OCR 识别冲突、短暂画面漏采和 OCR 时间近似会影响核验。不能据此断言视频真实画面或发言必然如此；若报告 Trace 表明使用 `MockProvider`，不能将该报告作为真实模型效果的证明。

## 判定规则

- **支持**：可定位的原始证据支持完整结论及其限定条件。
- **部分支持**：只支持部分事实项，或结论将有限证据扩大到更大范围；列明已支持与未支持部分。
- **不支持**：现有证据与结论直接冲突，或所给引用经核查不能支持该表述。注明是引用问题还是事实矛盾，避免混淆。
- **无法判断**：证据缺失、识别不清、覆盖不足或仅有未命中结果，尚不能确定。检索不到不等于事实为假。

对跨片段综合或已明确标注的有依据推断，解释推导依赖与不确定性；不要把合理推断误说成视频直接陈述，也不要仅因为不是逐字原话就否定综合摘要。

## 输出

优先遵守用户格式；默认输出审计范围与概览、逐条审计表，以及仅依据现有证据的建议修订。

表格包含：原结论、判定、原引用、核验依据及时间戳、问题、建议修订。不要直接修改平台原报告，除非用户另行授权且工具支持。

需要支持率时，写清“完全支持项数 / 本次拆分的事实项总数”，部分支持不计为完全支持，无法判断项保留在分母中；另列实际核验覆盖范围。没有事实项时不计算比例。该比例只描述本次审计，不外推为系统准确率、未见视频效果或模型可靠性。
